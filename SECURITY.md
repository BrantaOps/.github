# Security policy

Report a security issue to [support@branta.pro](mailto:support@branta.pro). We will review it and respond as quickly as we can. Do not report it through public GitHub issues, discussions, or social media.

The same policy is published at [branta.pro/disclosure](https://branta.pro/disclosure).

## Scope

- https://branta.pro
- https://guardrail.branta.pro
- Public repositories in the [BrantaOps](https://github.com/BrantaOps) organization

## Out of scope

- UI and UX issues with no security impact
- Denial of service
- Social engineering of Branta staff or customers
- Services operated by someone other than Branta
- Vulnerabilities in third-party dependencies. Report those to the project that owns them. A heads-up is welcome if Branta is affected.

## What to send

- A description of the issue
- The steps to reproduce it
- The URL or repository where it appears
- The affected version, if the issue is in an SDK
- Any proof-of-concept code or logs, with credentials redacted
- Whether you have disclosed it anywhere else

## Before you publish

Give us a reasonable time to fix the issue before you publish it. Do not access, change, or destroy customer data beyond what is needed to show the issue. Do not interrupt the service.

Once a fix is released, we are happy to credit you if you would like.

This policy covers security issues only.
